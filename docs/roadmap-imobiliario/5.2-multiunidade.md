# 5.2 — Administração multiunidade

Esforço G, Fase 5. Depende de 0.3 e 3.4 — o próprio roadmap justifica essa
dependência dizendo que "multiunidade multiplica a superfície de
RLS/RBAC; precisa da fundação de segurança já madura". Só foi construído
depois que 3.4 (permissões granulares) já estava em produção com o padrão
de rollout por flag validado.

## Decisão central de segurança

Vincular uma organização como unidade de uma rede **nunca** concede
acesso automático aos dados brutos (contatos, negócios) de outra
organização — nenhuma policy de RLS existente em `contacts`/`deals`/etc.
muda. O único caminho de acesso entre organizações é a função
`get_network_benchmark`, que devolve **apenas contagens agregadas**
(total de contatos, total de negócios, negócios em aberto, ganhos em 30
dias) por organização — nunca uma linha individual de contato ou negócio.

Isso evita exatamente o risco que o próprio roadmap aponta como motivo de
esperar 0.3/3.4 amadurecerem: expandir a superfície de RLS. Em vez de
expandir, a entrega mantém a superfície de RLS existente intacta e abre
um único túnel bem definido e auditável.

## O que foi entregue

- `supabase/migrations/0078_multiunidade.sql`:
  - `organizations.parent_org_id` (nullable, `on delete set null`) —
    marca uma organização como unidade de uma rede.
  - `get_network_benchmark(p_parent_org_id uuid)` — `security definer`,
    valida `is_org_admin(p_parent_org_id)` antes de devolver qualquer
    linha; devolve a organização matriz e todas as suas unidades
    (`parent_org_id = p_parent_org_id`) com contagens agregadas.
- `lib/supabase/types.ts`: `Organization.parent_org_id` e o tipo
  `NetworkBenchmarkRow`.
- `app/(app)/settings/rede/page.tsx`: página admin-only. Se a própria
  organização é uma unidade filha, mostra aviso de que o benchmark é
  visto pelo admin da matriz (evita uma unidade filha enxergar dados
  agregados de unidades irmãs que não são dela). Caso contrário, chama a
  RPC e renderiza a tabela comparativa.
- Link adicionado em `/settings` (bloco admin-only, junto dos outros
  links administrativos).
- `test/integration/rls.test.ts`: dois testes novos — admin da matriz
  recebe linhas agregadas de matriz+unidade após vínculo; usuário que não
  é admin da matriz recebe erro ao chamar a RPC com o `p_parent_org_id`
  da matriz.

## Vínculo entre organizações é ação de operação, não self-service

Não existe formulário para uma organização se auto-vincular como unidade
de outra rede — mesmo padrão já estabelecido em `real_estate_v2_enabled`
e `granular_rbac_enabled`: uma flag/vínculo que expande escopo de dados
entre organizações só é ativado por quem opera a plataforma (service
role), nunca pelo próprio usuário. Vincular é uma decisão comercial
(quem é matriz, quem são as unidades) que cabe ao time do OtimizIA
confirmar antes de qualquer dado cruzado aparecer.
