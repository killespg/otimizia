# 5.1 — Ecossistema de integrações

Esforço G, Fase 5 (escala/plataforma). O roadmap descreve este item como
"abrir a plataforma" para ferramentas de terceiros (Zapier/Make/n8n,
parceiros, integrações verticais do mercado imobiliário).

## O que já existe (entregue em 2.4, não duplicado aqui)

A fundação técnica deste item — a parte que é código — já foi construída
em Fase 2:

- **Webhooks de saída** (`docs/roadmap-imobiliario/2.4-webhooks-api-publica.md`):
  assinatura HMAC-SHA256, eventos via `crm_domain_events` + triggers,
  entrega assíncrona por worker cron.
- **API pública de leitura**: chaves de API com hash SHA-256 (nunca
  armazena o segredo em texto puro), escopo por organização, endpoints
  REST para contatos/negócios/imóveis.

Um Zapier/Make/n8n consegue se integrar hoje usando webhooks (gatilho) +
API de leitura (ação) — o que falta não é capacidade técnica de
integração, é **empacotamento e distribuição** dessa capacidade.

## O que não foi implementado nesta entrega, e por quê

Os itens restantes de 5.1 não são código a escrever — são processos de
negócio/parceria que exigem decisão e execução fora do repositório:

- **SDK publicado** (pacote npm/PyPI com cliente tipado para a API): é
  trabalho de código real, mas represento aqui como não feito porque
  antes de publicar um SDK público faz sentido a API de 2.4 rodar em
  produção por um tempo — mudar a superfície pública depois de um SDK
  publicado é muito mais caro que antes.
- **Registro de app OAuth com Zapier/Make/n8n**: cada plataforma exige
  cadastro de parceiro, revisão deles, e geralmente aprovação comercial
  (algumas cobram para listar). Isso é decisão/orçamento de negócio, não
  uma tarefa de engenharia que se resolve nesta sessão.
- **Revisão de segurança com parceiros**: due diligence formal (deles
  avaliando nós, ou nós avaliando o parceiro) é processo humano, não
  algo que se automatiza ou "implementa".

## Recomendação

Quando houver decisão de negócio para seguir com 5.1 além do que 2.4 já
cobre: (1) deixar a API pública rodando em produção por pelo menos um
ciclo de uso real antes de publicar SDK, (2) escolher 1 plataforma
(provavelmente Zapier, maior base de usuários pequenos negócios) para o
primeiro registro de parceiro em vez de tentar as três ao mesmo tempo.

foi verificada e coberta por testes em sua própria entrega.
